## 1단계: 변경 범위 확인

아래 명령을 실행합니다:

```bash
git status
git diff HEAD
```

변경사항이 전혀 없으면 즉시 중단하고 사용자에게 안내합니다:

> "리뷰할 변경사항이 없습니다. 코드를 작성하거나 수정한 후 다시 시도해주세요."

## 2단계: code-reviewer 서브에이전트 호출

변경된 파일 목록과 diff 전체를 컨텍스트로 포함하여 `code-reviewer` 서브에이전트를 호출합니다.

서브에이전트에게 전달할 컨텍스트:
- 변경된 파일 목록 (신규/수정/삭제 구분)
- `git diff HEAD` 전체 출력
- 프로젝트 스택: Next.js 15 App Router, TypeScript, TailwindCSS v4, shadcn/ui, Supabase

서브에이전트는 다음 형식으로 피드백을 생성합니다:

```
## 📋 코드 리뷰 요약
[전반적인 코드 품질과 주요 발견사항 요약]

## ✅ 잘한 점
- [긍정적인 측면들]

## 🔍 개선 필요 사항

### 🚨 심각도: 높음
- **파일**: path/to/file.tsx:라인번호
- **문제**: [문제 설명]
- **해결방안**: [코드 예시 포함]

### ⚠️ 심각도: 중간
...

### 💡 심각도: 낮음
...
```

## 3단계: 결과 출력

서브에이전트의 리뷰 결과를 대화창에 그대로 출력합니다.

각 지적사항에 `파일명:라인번호` 형식을 포함하여 사용자가 해당 위치로 바로 이동할 수 있도록 합니다.

## 4단계: 다음 액션 안내

리뷰 출력 후 사용자에게 안내합니다:

> "리뷰 결과를 GitHub PR 인라인 코멘트로 올리려면 `/git-code-review-pr <PR번호>`를 사용하세요."
